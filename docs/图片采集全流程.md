# 图片采集全流程与代码说明

> 这份文档只讲「地标图」这一条链路：从「国家」走到「一张能上屏的 1080px 照片」。
> 国家档案的文字采集见 `docs/全量采集.md`。
> 所有命令都在仓库根目录执行（`E:\workbuddy\atlas-mundi`）。

---

## 0. 一条命令

```bash
# 全量/增量选图 → 视觉复核 → 出图 → 打包 → 分发
python scripts/fill_images.py --all        # 1) 检索 + 打分 + 三档闸门
python scripts/verify_images.py --all      # 2) 看图复核，不合格当场换（可选但强烈建议）
python scripts/optimize_images.py --all    # 3) 出 1080 webp + 240 缩略图
python scripts/build_cards.py              # 4) 合并成前端读的 cards.json
python scripts/upload_obs.py --bucket atlas-mundi-1419 --region cn-east-3 --only data
```

代理走环境变量，脚本不去猜：

```bash
set HTTPS_PROXY=http://127.0.0.1:7897      # Windows cmd
export HTTPS_PROXY=http://127.0.0.1:7897   # bash
```

## 1. 数据从哪来

| 源 | 拿到什么 | 用途 |
|---|---|---|
| **Wikidata** | 国家 QID、P18（条目的"代表图"）、P31/P17 | 国家档案 + 候选池第一档 |
| **维基百科（中文/英文）** | 条目正文配图、首图、摘要 | 候选池第二、三档 |
| **Wikimedia Commons** | 全文检索结果、imageinfo（尺寸/授权/作者）、分类 | 主力的图片源 + 全部授权信息 |
| **DeepSeek 视觉模型** | 「这张画面是不是这处地标」 | 最后一道闸门 |

为什么必须用 Commons 而不去别处抓：**授权信息是结构化的**（`extmetadata` 里有 LicenseShortName / Artist / LicenseUrl），页面上要显示"CC BY-SA 4.0 · 摄影者"。截图站、搜索引擎图片、National Geographic 都没有这一层，法律和展示上都不能直接上。

## 3. 七步流程

### 3.1 `collect.py` —— 国家档案

输入 ISO 列表 → 输出 `data/<iso>.json`。

取 QID → 摘要/历史 → 首都、大洲、语言、质心 → 轮廓几何。断点续跑，单国失败不影响其他。

```bash
python scripts/collect.py CN --check    # 先体检四个域名（Wikidata/中文维基/Commons/upload）
python scripts/collect.py --all
```

### 3.2 `build_landmarks.py` —— 地标清单

模型按国家列 5~6 处地标，每处给 `zh / en / kw / must`：

```json
{"zh": "罗本岛", "en": "Robben Island", "kw": "Robben Island Cape Town", "must": "robben"}
```

**为什么不让模型直接给图片**：模型给不出真实文件名，给了也是编的。
所以清单只是"检索词"，能不能落地由 Commons 的真实检索结果裁决——编出来的地标会自然被淘汰。

- `kw` 是检索串（越具体越好，带上城市名减少歧义）
- `must` 是**文件名闸门**：候选文件名必须包含它（去空格、小写后做子串判断）

### 3.3 `fill_images.py` —— 选图（核心）

#### 候选池（4 档，共 6 次尝试）

```python
ATTEMPTS = [
    ("curated", "strict"),   # Wikidata P18：编辑挑的代表图
    ("curated", "relaxed"),
    ("article", "strict"),   # 维基正文配图：编辑挑过，比全文搜索准一个量级
    ("commons", "strict"),   # Commons 关键词全文检索
    ("late",    "strict"),   # 英文维基首图（解析条目名会跑偏，排后面）
    ("curated", "loose"),    # 兜底
]
```

#### 打分

```python
def score(cand, meta, must, tier, aliases=None):
    # 硬淘汰
    if w < tier["min_w"]:            return None, "宽度不足"      # 900 / 800 / 640
    if ar > tier["max_ar"]:          return None, "宽高比超标"    # 2.2 / 3.2 / 4.5
    # 加分
    + 清晰度（宽度阶梯）  + 比例接近 1.45（面板是 4:3）
    + 专名命中（must / 多语言别名）
    + 质量徽章（Commons Featured +1.5 / Quality +0.8，**艺术复制品不给**）
    - 细节惩罚 -3.0（window / ceiling / interior / stair / furniture…）
    - 全景惩罚（宽高比 2.2~3.2 之间）
```

池子权重（`POOL_WEIGHT = 0.8`）不再是第一关键字，高分图能翻盘：

```python
out.sort(key=lambda x: -(x["score"] - POOL_WEIGHT * x["order"]))
```

#### 闸门（这一层的全部家当）

| 闸门 | 挡什么 | 在哪 |
|---|---|---|
| `min_w / max_ar` | 太小、太扁 | `score()` |
| `must_ok` | 文件名不含专名（防同名不同地） | `score()` |
| `HARD_BAD_RE` | 施工/明信片/战场/军队/蝴蝶/邮票/海图/告示牌/`国家 - 地区.PNG` 定位图 | `bad_kind()` |
| `BAD_PREFIX_RE` | `Location…`、`map…`、`OSM-…` | `bad_kind()` |
| `ART_REPRO_RE` | PD-Art / Prints of / Engravings（名画复制品） | `quality_bonus()` + `bad_kind()` |
| `is_junk` | 雕塑、展陈、建筑设施 | 候选过滤 |
| `avoid` 列表 | 同一个名字在别的国家也有（里约基督像 vs 基辅圣索菲亚） | `rank_pool()` |
| 多语言别名 | 泛词 must 换成 Wikidata label/alias（`mirror` → `galerie des glaces`） | `aliases_for()` |
| 同国去重 | 同一个 Commons 文件不能挂两处 | 国家层面 `used_names` |

### 3.4 `verify_images.py` —— 看图的最后一道闸

规则筛得掉尺寸不对、文件名像地图的，**筛不掉"画面上根本不是这处地标"**。
这一步真的把图发给多模态模型看：

```python
MODEL = "deepseek-v4-flash-vision-exp"
THUMB = 384          # 单张封顶 384px，官方按尺寸折 token
PRICE = {"peak": (3.0, 9.0), "idle": (1.5, 4.5)}   # 元/百万 token
```

判定是**一国一次请求、多图批量**（省掉每次的 prompt 开销）：

```python
judge(country, [(caption, jpeg_bytes), ...]) -> [(ok, why), ...]
```

不合格 → 从候选池取下一张 → 下载 → **再判一次** → 不合格继续换；候选试完（`MAX_TRIES=3`）就删掉这一格（宁缺勿错）。

四重预算保险，保证不会无限烧钱：

1. 候选池有限（一个地标最多 26 个）
2. 判定缓存 `data/_vision_cache.json`（**同一张图永不重复验**）
3. 金额硬闸门 `--budget`（元）
4. 轮数 + 收敛 `--max-rounds`（本轮零改动就退出）

```bash
python scripts/verify_images.py --all --oracle          # 只判定不换（体检，最便宜）
python scripts/verify_images.py --all --budget 3         # 判定 + 换 + 再判
python scripts/verify_images.py --only YE DK TR --oracle # 抽查几个国家
```

### 3.5 `optimize_images.py` —— 出图规格

```python
DETAIL_W, DETAIL_Q = 1080, 75     # 面板图区 360 CSS px；2× 屏 720、2×+125% 缩放 900、手机 3× 1080
THUMB_W, THUMB_Q, THUMB_H = 240, 78, 180   # 胶片带每张只显示 64×46，240 已有 3.75 倍余量
```

1080 是折中：桌面 2 倍屏完全够，手机 3 倍屏到 1.9 倍，肉眼分辨不出。

### 3.6 `build_cards.py` / `sync_index.py` —— 前端数据

`cards.json` 把 236 国合并成**一个文件**（0.9 MB / gzip 0.34 MB），面板点开就能整段渲染，不必再等国别档案。字段白名单：

```python
TEXT_KEYS = ('iso_a2','iso_a3','name_zh','name_en','qid','capital','continent',
             'centroid','geometry','summary_text','history_text','custom_text',
             'custom_facets','review_short')
# 图片只留 url / thumb_url / caption_zh / license / author（remote_url 一条 200 字符，砍掉）
```

### 3.7 `upload_obs.py` —— 分发

华为云 OBS `atlas-mundi-1419` / `cn-east-3`，防盗链白名单：

```python
ALLOW = ["https://zzq1419.github.io", "http://127.0.0.1", "http://localhost"]
```

前端 `assetSrc()` 先试 OBS、失败回退仓库相对路径（`OBS_MISS` 记住哪个国家挂了，后续不再试）。

## 6. 踩过的坑（按踩到的顺序）

1. **`thumbwidth` 是请求值，不是真实宽度**。原图 < 请求宽度时 Commons 不放大、直接回原图（URL 带 `thumbnail_unscaled`），但字段仍填 1400 —— `width>=900` 这道闸对这类文件**完全失效**。→ 检测 `thumbnail_unscaled` 就回落 `ii["width"]`，另存 `orig_w`。
2. **P18 / 首图不是"这处地标"**。它只是"这个条目最常配的图"：奇琴伊察拿到过 1844 年石版画，孟加拉国会拿到过巴基斯坦邮票。
3. **`must` 会误杀外语文件名**。`must=cologne` 把 `Kölner Dom von Osten` 判出局；`must=mirror` 把 `Galerie des Glaces` 判出局——这两张都是最好的图。→ 用 Wikidata label/alias 做多语言闸门。
4. **泛词 `must` 没有鉴别力**。`mirror` 会放进一张"酒吧镜子商品照"。→ `GENERIC_MUST` 列表，命中就换成别名闸门。
5. **同名不同国**。Commons 候选池里同时有马德里 / 塞维利亚 / 卡拉塔尤德 / 塔萨科尔特 / 关岛五座"西班牙广场"，选中了马德里那张。
6. **质量徽章会奖励艺术复制品**。红富士木版画（Featured）赢过富士山实景照。→ `ART_REPRO_RE` 命中时不给徽章分，且在 `bad_kind` 里淘汰。
7. **人名/电影/书名混进来**。"Timothy Hill" 是一个美国政客的名字，不是那座山。
8. **卫星图完全合规**。基里巴斯的 P18 是 Sentinel-2 卫星照、NASA 地球观测图、NGDC 三维海底地形图——尺寸、比例、文件名全过闸。
9. **"含专名但不是代表作"**。`Visitor Center, Arikok Park`、`Gorongosa Park Gate`、`NSGA Midway Sign` 都含专名；全库 20 张这类图，**严格文件名规则能放行 19 张**。
10. **地区条目的定位图**固定叫 `Solomon Islands - Santa Isabel.PNG`，靠词边界抓不到，只能加一条 `\s-\s[^.]*\.PNG$`。
11. **OBS 防盗链**：本地 `localhost:xxxx` 端口不在白名单，直接 403；线上 referer 正常。
12. **GitHub Pages 每个请求固定 ~1.2s TTFB**（境外），大文件走 jsDelivr（`geo/c0.json` 28s → 2~3s）。
13. **CDN 会缓存裸路径**：`/` 的 HTML 缓存 1 小时，重新部署也不 purge。部署后必须带随机参数或访问 `/index.html` 核对 build 号。
14. **只转 webp 不传 jpg**：`refill` 写出来的是 `.jpg`，不做 `optimize_images` 就上传，缩略图会 404。
15. **`verify_images.refill` 里 `zh` 从未赋值**：换图路径一走到更新条目就 `NameError`。之前只跑过 `--oracle`（只判定不换），所以一直没暴露。

## 7. 判断一条经验

**"更清晰"和"是那处地标"是两件事。** 自动流程只能保证前者。
所以任何批量换图，落盘前必须过一遍 `preview_lowres.py` 拼的核对表——2026-11-04 那轮 12 张候选里，肉眼当场砍掉 5 张（线稿剖面图、奥巴马合影、海豚、木棉树、动物照）。

同理，模型判定也不是终审：抽查 12 条里 4 条是模型错（阿鲁巴那座灯塔本名就叫 California Lighthouse；赫德岛的"大本钟"就是那座火山）。而 `Pigeon Point Lighthouse` 在加州、`Castel San Giorgio` 在意大利，是模型对、我错。**先看文件名，再下结论。**

## 8. 结构化约束能不能当"采集时"的硬闸（2026-11-05 实测）

`audit_constraints.py` 上线后，很自然会想问：**能不能在选图时就挂上它，把错图挡在门外？**
`gate_eval.py` 在**候选级**上量了一遍（30 个地标 × 前 10 个候选 = 139 张，全部过视觉判定对照）：

| 指标 | 数值 | 说明 |
|---|---|---|
| 有结构化信号的候选 | 58 / 139（42%） | 其余 81 张既无 P180 也无 GPS |
| 闸判"冲突/贴边界" | **1 张** | 几乎不触发 |
| 其中视觉也认为是错的 | 0 张 | 唯一那张还是**误杀** |
| 闸放行后视觉判错 | 11 / 65（**17%**） | 这才是真问题 |

**结论：不能当采集时的硬闸。** 三个原因：

1. **覆盖率不够**：候选多来自 P18 / 正文配图，这两类经常没有 P180 和 GPS。
2. **召回太低**：它只能抓"坐标或声明明确落在别国"的图，而候选池里的错图 98% 不是这类。
3. **它挡不住真正的病**：放行的 11 张错图全是"**本国某处，但不是这处地标**"——
   室内佛像（仰光大金塔）、解说牌（冈比亚）、蟾蜍（乌拉圭）、矿工人物（玻利维亚）、
   街道建筑（波托西）。这类只能靠"看画面主体"判断。

所以它的正确定位是**事后审计 + 弱信号**，不是门神。真正的门神必须是视觉/多模态那一层。

**顺带修正的一个 bug**：属地（MP 北马里亚纳、PR 波多黎各、GU 关岛、AS 美属萨摩亚）的
`P17` 写的是主权国（US），于是"这张图在北马里亚纳吗"会被判成冲突，实测误杀了天宁岛的
`BANZAI CLIFF`。已在 `audit_constraints.py` 加 `sovereign_isos()`：把主权国也算作可接受。
